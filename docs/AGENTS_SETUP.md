# Agents Setup Guide

Autonomous content pipeline: Scraper → Analyzer → Writer → Publisher.

## Architecture

```
Scraper (15-20 min)
  ↓ scrapes Zap + VivaReal
  ↓ stores to Supabase listings table
  
Analyzer (10 min)
  ↓ detects: new launches, price moves, hotspots
  ↓ ranks by relevance (top 3)
  
Writer (10-15 min)
  ↓ Claude 3.5 Sonnet generates posts
  ↓ 200-300 words, opinionated tone
  
Publisher (2 min)
  ↓ quality gates (70% threshold)
  ↓ retry logic (1min, 5min, 15min)
  ↓ Slack alerts
```

## Prerequisites

1. Supabase project created + env vars set (see SUPABASE_SETUP.md)
2. Environment variables in `.env.local`:
   ```
   NEXT_PUBLIC_SUPABASE_URL=
   NEXT_PUBLIC_SUPABASE_ANON_KEY=
   SUPABASE_SERVICE_ROLE_KEY=
   CLAUDE_API_KEY=
   FIRECRAWL_API_KEY=
   SLACK_WEBHOOK_URL= (optional)
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

## Running Agents Locally

### Step 1: Build
```bash
npm run build
```

### Step 2: Run Full Pipeline
```bash
npm run agent:run
```

This runs all agents sequentially:
- Scraper → stores listings
- Analyzer → detects trends → tmp/analyzed_stories.json
- Writer → generates posts → tmp/generated_posts.json
- Publisher → publishes + Slack alert

### Step 3: Monitor Output

Check `tmp/` folder:
- `analyzed_stories.json` — stories selected by analyzer
- `generated_posts.json` — posts generated by writer (before publish)

## Agent Details

### Scraper Agent (`src/agents/scraper.ts`)
**Input:** URLs (Zap + VivaReal)  
**Output:** Supabase listings table

What it does:
1. Firecrawl scrapes Zap Imóveis + VivaReal search results
2. Parses HTML → extracts price, bedrooms, bairro, etc.
3. Deduplicates by (source, url)
4. Stores in Supabase `listings` table
5. Outputs: count of new vs existing

**Duration:** ~15-20 min (depends on Firecrawl API)

**Sample output:**
```
✓ Zap: 15 listings scraped
✓ VivaReal: 18 listings scraped
✓ Stored: 20 new, 13 existing
```

### Analyzer Agent (`src/agents/analyzer.ts`)
**Input:** Supabase listings table (last 24h)  
**Output:** tmp/analyzed_stories.json

What it does:
1. Detects **new launches** (2+ listings per neighborhood in 24h)
2. Detects **price movements** (30%+ range per neighborhood)
3. Detects **neighborhood hotspots** (5+ listings in recent data)
4. Ranks by relevance score (new > price > hotspot)
5. Selects top 10 stories

**Output structure:**
```json
[
  {
    "type": "new_launch",
    "neighborhood": "Praia do Farol",
    "count": 5,
    "relevanceScore": 100,
    "details": "5 new listings in Praia do Farol",
    "listings": [...]
  }
]
```

### Writer Agent (`src/agents/writer.ts`)
**Input:** tmp/analyzed_stories.json (top 3 stories)  
**Output:** tmp/generated_posts.json

What it does:
1. For each top story, calls Claude 3.5 Sonnet
2. Generates opinionated post (200-300 words)
3. Includes factual data (prices, bairros, trends)
4. Tags, featured image search query, CTA
5. Validates response format

**Sample post:**
```json
{
  "title": "Praia do Farol: refúgio de milionários com preços que voam",
  "slug": "praia-farol-milionarios",
  "body": "250 words of opinionated analysis + data...",
  "tags": ["praia-farol", "residencial", "lançamento"],
  "featuredImage": "luxury apartment beach sunset",
  "cta": "Quer acompanhar lançamentos? Assine newsletter"
}
```

**Duration:** ~10-15 min (3 API calls to Claude)

### Publisher Agent (`src/agents/publisher.ts`)
**Input:** tmp/generated_posts.json  
**Output:** Published posts in Supabase + Slack alert

What it does:
1. Validates each post against **quality gates** (70% threshold):
   - Has title, body, slug, tags
   - No duplicate slug
   - No extreme clickbait ("CHOCANTE" alone)
   - Contains data (prices, bairros, %)
2. POSTs to `/api/publish` endpoint
3. Retry logic if POST fails:
   - Fail → wait 1min → retry
   - Fail → wait 5min → retry
   - Fail → wait 15min → retry
   - 3 fails → log error
4. Slack alert with summary

**Quality gates (7 checks):**
- ✓ Has title
- ✓ Has body (min 50 chars)
- ✓ Has slug
- ✓ Has tags (min 2)
- ✓ Slug length ≤ 100
- ✓ No extreme clickbait
- ✓ Contains data

**Score calculation:** `(passed_gates / total_gates) * 100`  
**Threshold:** ≥70% to publish

**Sample output:**
```
✅ [PASSED QC] Praia do Farol: refúgio de milionários...
   Score: 100%
   🌐 Published at http://localhost:3000/posts/praia-farol-milionarios

⚠️ [REJECTED] Bad post title...
   Score: 42% (threshold: 70%)
   Failures: Has data/context, No extreme clickbait
```

## Cron Scheduling (3x Daily)

To run agents automatically 3 times daily (6am, 12pm, 6pm):

### Option 1: Vercel Cron (Production)
Add to `vercel.json`:
```json
{
  "crons": [
    {
      "path": "/api/cron/run-agents",
      "schedule": "0 6 * * *"
    },
    {
      "path": "/api/cron/run-agents",
      "schedule": "0 12 * * *"
    },
    {
      "path": "/api/cron/run-agents",
      "schedule": "0 18 * * *"
    }
  ]
}
```

Then create `src/app/api/cron/run-agents/route.ts` that executes the pipeline.

### Option 2: External Scheduler (Upstash, GitHub Actions)

Use Upstash QStash to POST webhook to your app 3x/day.

### Option 3: Local Development (Manual)
```bash
# Terminal 1: Start dev server
npm run dev

# Terminal 2: Run agents when ready
npm run agent:run
```

## Troubleshooting

### ❌ Scraper fails
- Check Firecrawl API key + quota
- Verify internet connection
- Check if Zap/VivaReal URLs are still valid
- Try running manually: `npm run agent:scraper`

### ❌ Analyzer finds no stories
- Check if listings table has data (run scraper first)
- Lower the thresholds (e.g., change `count >= 2` to `count >= 1`)
- Check timestamps (analyzer looks at last 24h)

### ❌ Writer generates bad posts
- Check Claude API key + quota
- Review generated post in `tmp/generated_posts.json`
- Adjust prompt in writer.ts if needed

### ❌ Publisher rejects posts
- Check quality gate thresholds (default: 70%)
- Post might be missing required fields (title, body, tags)
- Check post for clickbait keywords

### ❌ Slack alert doesn't send
- Verify `SLACK_WEBHOOK_URL` is set and valid
- Check Slack channel permissions
- Look for network errors in console

## Performance Tuning

### Reduce Scraper Duration
- Decrease number of pages scraped
- Increase Firecrawl timeout (currently 30s)
- Cache previous URLs to skip

### Reduce Writer Duration
- Decrease batch size (currently 3 posts/run)
- Use cheaper model (Claude 3 Haiku instead of Sonnet)

### Increase Reliability
- Add database backups
- Log all API calls
- Monitor rate limits (Claude, Firecrawl)

## Monitoring

**What to watch:**
1. Number of posts published per day (target: 3-5)
2. Quality gate pass rate (target: >70%)
3. API costs (Claude ~R$200-400/mth, Firecrawl ~R$100-200/mth)
4. Database growth (listings table)
5. Slack alert frequency (should be 3x/day)

**Metrics to track:**
```
Posts published: 15/day
Stories analyzed: 30/day
Quality pass rate: 85%
Avg post length: 250 words
API calls/day:
  - Firecrawl: 6 (2 sources × 3 runs)
  - Claude: 9 (3 posts × 3 runs)
  - Supabase: ~50+ queries
```
